# Kryden Layout Lab: measure DayZ UI in-game

A development tool. It opens test layouts in the running game and writes the rectangle the engine
computed for every widget to the client log, so layout rules can be measured instead of guessed. The
findings it produced are in `docs/dayz-ui-findings.md`. Do not ship it to players (see the README).

## Pieces

| file | what it is |
|---|---|
| `KrydenLayoutHudDesigner_Client/gui/layouts/lab/kld_lab_01_sizing.layout` | pixel vs proportional, `scaled`, child inside a proportional parent (hand written) |
| `KrydenLayoutHudDesigner_Client/gui/layouts/lab/kld_lab_02..08_*.layout` | generated by `lab/gen_lab_layouts.py` |
| `KrydenLayoutHudDesigner_Client/gui/layouts/lab/kld_lab_menu.layout` | panel with one button per test |
| `KrydenLayoutHudDesigner_Client/data/inputs.xml` | key `UAKLDLabMenu` (default **Insert**, rebindable in Options > Controls > Kryden Layout Lab) |
| `KrydenLayoutHudDesigner_Client/scripts/5_Mission/lab/KLD_LabMission.c` | the key opens/closes the menu (factory + `EnterScriptedMenu`: the engine holds the ref) |
| `KrydenLayoutHudDesigner_Client/scripts/5_Mission/lab/KLD_LabMenu.c` | opens each test and writes the rectangles to the log |
| `KrydenLayoutHudDesigner_Client/scripts/5_Mission/lab/KLD_LabShowcase.c` | test 08: builds the component library from script |
| `lab/gen_lab_layouts.py` | regenerates 02-08 (`python lab/gen_lab_layouts.py`) |
| `lab/validate_layout.py` | checks that no attribute, value, style (vanilla or this mod's) or font was invented. Passing it does not prove the layout renders |

The test layouts use only what exists in vanilla (`P:\gui`) plus this mod's atlas styles (tests 07
and 08). Text is UTF-8 without BOM, like vanilla.

## Log format

When a test opens, `KLD_LabMenu` walks the widget tree and writes one line per widget to the client
log (`%LOCALAPPDATA%\DayZ\script_*.log`; if it is not there, look in the `.RPT` in the same folder):

```
[KLD_LAB] test=01_sizing phase=immediate screen=1920x1080 depth=1 name=s01_px_100x100 type=PanelWidget vis=1 x=40 y=40 w=100 h=100 decl_pos=40 40 decl_size=100 100
```

- `x y w h` = `GetScreenPos / GetScreenSize` (screen pixels). `decl_*` = `GetPos / GetSize`.
- 3 phases per test: `immediate` (right after `CreateWidgets`), `delayed` (250 ms later) and
  `after_update` (after `Update()` on every widget). If `immediate` is zero and `delayed` is not, the
  engine only computes on the next frame. If only `after_update` fixes a spacer's children, that
  spacer needs `Update()`.
- Anything visual (layers, borders, fonts) needs a screenshot (Steam F12 or PrintScreen; prefer PNG).

## Protocol

1. Generate the atlas (`python tools/gen_atlas.py`), pack `KrydenLayoutHudDesigner_Client` and start
   server + client with `-mod=@KrydenLayoutHudDesigner`.
2. In the world, press **Insert**. Click each test (01 to 08). ESC closes the test and returns to the
   buttons. Take a screenshot of tests 04 to 08.
3. Close the menu, change the resolution in Options > Video and repeat step 2. Suggested order:
   1920x1080, 2560x1440 (if the monitor allows) and 1280x720.
4. Read the `[KLD_LAB]` lines of each session and compare resolutions.

## What each test decides

`W x H` = rectangle of the root `kld_lab_0N_root` (the real screen/window size).

- **01 sizing**: is an exact 100x100 the same in every resolution (physical pixels) or scaled? What
  does `scaled 1` do? Proportional child inside a proportional parent; mixed axes.
- **02 anchors**: nine squares at `position 20 20` with `halign left|center_ref|right_ref` x
  `valign top|center_ref|bottom_ref`; the default anchor; `bottom` vs `bottom_ref`; a proportional
  offset from the right edge.
- **03 spacers**: GridSpacer with (Padding, Margin) = (10, 0), (0, 10), (10, 25); the same for
  WrapSpacer; `content_halign center`; `"Size To Content V"` on load.
- **04 layers** (visual): overlapping pairs, red declared first and blue later: no priority; red 10 /
  blue 1; red 1 / blue 10; a red child with 999 inside a parent with 1 against a blue sibling with 5.
- **05 nine-slice and images** (visual + rectangles): vanilla panel styles tinted amber on a dark
  background at several sizes (border thickness per resolution); the DayZ logo with the four
  `fixaspect` values, `mode additive` + `"src alpha" 1`.
- **06 fonts** (visual): the same sentence with Portuguese accents in SDF (Book/Light 24, Book 72) and
  bitmap fonts at several sizes; `f12` is the ASCII control line. A missing glyph shows as a gap or
  box; mojibake means a file encoding problem, not the font.
- **07 own atlas** (visual + rectangles): cards, buttons and badges with the own r10/r6 styles; button
  text in the `ButtonWidget` itself vs a child `TextWidget`; corners at several sizes including below
  the 2r+4 minimum; a ring over amber (transparent center?); black 50% over amber (sRGB or linear
  blending?). Uses the yellow primary from before D-12 on purpose.
- **08 components** (interaction + rectangles): the v0 library created from script inside empty
  containers; hover, click (the status line and the log show `Click: <label>`), disabled; and the
  round 7 comparison row of eight primary candidates (static).

## Results in short

| round | setup | outcome |
|---|---|---|
| 1 | 1600x900 window | exact units scale by 900/1080; anchor offsets point inward; Padding/Margin inverted vs CSS; priority order; `scaled` does nothing |
| 2 | 1920x1080 | linear scaling confirmed (round 1 x 1.2); vanilla panel styles have torn edges; logo draws with additive + src alpha; all accents render |
| 3 | 1280x720 | x2/3 exact on 114 widgets; WrapSpacer filling the exact width wraps differently; `Outline` stays 2 px (physical) |
| 4 | test 07 at 1080p, 900p, 720p | own atlas renders; corner is physical pixels; 2r+4 minimum; linear blending; `"text color"` ignored on TextWidget; ghost button alpha hides its text |
| 5 | test 08 at 1080p, 720p | hover/click/disabled with exact colors; script children laid out on the next frame; a component created without parent stayed on screen after closing |
| 6 | test 08 after fixes, 3 resolutions | zero `SCRIPT (E)`, nothing left on screen; dark text on light stays thin whatever its color |
| 7 | comparison row, 1080p and 720p | bold shadcn primary chosen (D-12) |

Every round: zero `SCRIPT (E)` in the client log. The labels were Portuguese when measured; this copy
uses English labels with the same widgets and sizes.

## Still open

- The library with D-12 (bold primary button and badge: hover, disabled) at 1080p and 720p.
- Bold bitmap at 1440p/4K; `TextWidget.SetBold` and `"bold text"` on SDF.
- Non-16:9 resolutions (not offered in the game's video options).
- Whether the imageset `@2x` texture is used at high resolutions.
- `fixaspect` with `imageTexture`; isolating `"src alpha"` vs `mode additive`.
- Round 5 bug: once, test 08 received the tree of test 07 and built its components without a
  parent. It did not reproduce in round 6; the guards (null parent refused, showcase only on the 08
  containers) and the diagnostic log lines stay.
