# Kryden Layout HUD Designer

> **Work in progress — not finished.** This is a snapshot of a design system that is still being
> built. The parts marked as tested were tested in-game; everything else is a description of intent,
> not a promise. APIs, names and tokens may change.

A shadcn/ui-style design system for DayZ UI, written in Enforce Script:

- **Tokens**: a dark color palette (shadcn/ui based), radii 0 / 6 / 10 px, text scale 18 / 16 / 14,
  a 4 px grid, all expressed in 1920x1080 reference units.
- **Own nine-slice atlas**: white rounded corners (fill and 1 px ring, radii 6 and 10) registered as
  widget styles, tinted by `color` / `SetColor`.
- **Generated prefabs and four components**: `KLD_Button`, `KLD_Badge`, `KLD_Card`, `KLD_Separator`
  (five variants: primary, secondary, outline, ghost, destructive).
- **Generators** (Python) that write the tokens, the prefab `.layout` files and the atlas, plus a
  validator that rejects any `.layout` attribute, value, style or font that does not exist in vanilla.
- **Kryden Layout Lab**: an in-game menu (key Insert) with 8 test layouts that writes every widget
  rectangle to the client log. Most rules in `docs/` were measured with it.

## Requirements

- DayZ Tools (Steam). `tools/gen_atlas.py` calls `ImageToPAA.exe` from the default Steam path; edit
  `IMAGE_TO_PAA` at the top of the script if yours is elsewhere.
- A `P:` drive with the extracted game data (`P:\gui`, `P:\scripts`), only for `lab/validate_layout.py`.
- Python 3 (+ Pillow for `tools/gen_atlas.py`).
- A PBO packer that lets you set the prefix. `build.ps1` uses Mikero DePboTools (`MakePbo`, `ExtractPbo`).

## Try it

1. Generate the atlas texture (writes `gui/textures/kld_ui_atlas.paa`, and rewrites the imageset and
   styles with the same content):

   ```powershell
   pip install pillow
   python tools/gen_atlas.py
   ```

2. Pack `KrydenLayoutHudDesigner_Client` with the prefix
   `Kryden\KrydenLayoutHudDesigner\KrydenLayoutHudDesigner_Client` and put the PBO in
   `@KrydenLayoutHudDesigner\addons`. `build.ps1 -NoDeploy` does it and refuses a PBO whose prefix
   came out different. Sign it with your own key if your server verifies signatures.
3. Load it on server and client with `-mod=@KrydenLayoutHudDesigner`. The PBO is `type = "mod"`
   (never `servermod`: a client that loads a servermod PBO breaks).
4. In game, press **Insert** (rebindable in Options > Controls > Kryden Layout Lab) and open
   **08 Components**: it builds the library from script and is the usage example
   (`scripts/5_Mission/lab/KLD_LabShowcase.c`).
5. Acceptance: `script_*.log` without any `SCRIPT (E)`. That is necessary, never sufficient: look at
   the screen.

For file patching or Workbench, place the folder at `P:\Kryden\KrydenLayoutHudDesigner\` so the
prefix matches the path on disk. For packing alone the location does not matter.

## Use it in your own mod

The components are in `3_Game`, so code in your `3_Game`, `4_World` or `5_Mission` can use them.

```c
class MyMenu extends UIScriptedMenu
{
	protected ref array<ref KLD_Button> m_Buttons = new array<ref KLD_Button>;   // REQUIRED: keep the refs

	protected void Build(Widget holder)
	{
		KLD_Button ok = new KLD_Button(holder, "Confirm", EKLDVariant.PRIMARY);
		ok.m_OnClick.Insert(OnConfirm);
		m_Buttons.Insert(ok);

		KLD_Card card = new KLD_Card(holder, "Server", "Community server, 64 players");
		m_Buttons.Insert(new KLD_Button(card.GetFooter(), "Join", EKLDVariant.PRIMARY));

		new KLD_Badge(holder, "New", EKLDVariant.PRIMARY);
		KLD_Separator.Create(holder);
	}

	void OnConfirm(KLD_Button button) {}
}
```

Full API and rules: [docs/components.md](docs/components.md).

### Option A: as a dependency (recommended)

1. Keep this PBO as its own mod (`@KrydenLayoutHudDesigner`) and load it before yours.
2. In your `config.cpp`, make your patch load after it:

   ```cpp
   requiredAddons[] = {"DZ_Data", "DZ_Scripts", "KrydenLayoutHudDesigner_Client"};
   ```

3. Remove the lab before shipping to players, or every player gets an Insert key that opens a test
   menu: delete `scripts/5_Mission/lab/`, `gui/layouts/lab/` and `data/inputs.xml`, and remove the
   `inputs = ...` line from `config.cpp`. Keep `scripts/5_Mission/` with its placeholder file: the
   folder is listed in `files[]`. The `LAB_*` constants can stay. **Not tested.**

### Option B: copy it into your own PBO

1. Change the prefix everywhere it is written: `$PBOPREFIX$`; `dir`, `inputs` and every `files[]`
   in `config.cpp`; `PREFIX` in `tools/gen_atlas.py` and `tools/gen_components.py`; the `LAB_*`
   paths in `scripts/3_Game/KrydenLayoutHudDesigner_Constants.c`. Then regenerate (below).
2. Rename what would collide if another mod also ships this library: the `KLD_*` / `EKLD*` script
   classes (two mods defining the same class do not compile together), the imageset `Name "kld_ui"`
   and the `kld_*` style names (what happens on a style name collision is not tested), and the
   `CfgPatches` / `CfgMods` class names.

### The prefix rule

The PBO prefix must be the exact string that `config.cpp`, the imageset `path` and the script
constants use. A mismatch loads zero files without one line of log. A multi-segment prefix is fine
(Community Framework packs `JM\CF\Scripts`). After packing, check it:

```powershell
ExtractPbo.exe -P -L KrydenLayoutHudDesigner_Client.pbo   # look for the prefix= line
```

Also check that the `.pbo` file exists and is newer than your sources: MakePbo can exit 0 without
packing. In Windows PowerShell 5.1, do not append `2>&1` to a native tool call.

## Regenerate after changing tokens or prefabs

```powershell
python tools/gen_components.py   # KLD_Tokens.c + gui/layouts/kld/*.layout
python tools/gen_atlas.py        # atlas .paa + imageset + styles
python lab/gen_lab_layouts.py    # lab layouts 02-08
python lab/validate_layout.py "KrydenLayoutHudDesigner_Client/gui/layouts/kld/*.layout" "KrydenLayoutHudDesigner_Client/gui/layouts/lab/*.layout"
```

Never edit `scripts/3_Game/kld/KLD_Tokens.c` or `gui/layouts/kld/` by hand. Passing the validator
means nothing was invented; it does not prove that the layout renders.
